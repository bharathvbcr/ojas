2. Safety #

  1. One GPU job at a time. Launch every heavy command through mac_heavy.sh; it holds one lock (MAC_HEAVY_LOCK), refuses below MAC_HEAVY_MIN_FREE_GB (default 15) free, and sets CARGO_BUILD_JOBS=2 [V header]. Never start a GPU run beside owner-bench-stepcost.sh or the merge batch. Check ListAgents/GitPulse for a live GPU owner first.
  2. Kill only your own PIDs. Record the PID at launch and kill <pid>. Never pkill, killall or pkill -f. pid 30722 is not yours. For the kill -9 resume test, kill the training pid you started, not the mac_heavy.sh wrapper (the wrapper's SIGTERM path stops the whole tree [V header]).
  3. memguard SIGTERMs any single process above 32 GiB (footprint, 2 s samples, SIGKILL 10 s later) and the largest process of 2 GiB or more under critical pressure for 3 samples. It writes no log on this Mac: a kill shows as signal 15 with no mac_heavy footprint message [V header, Lappi-decision/CLAUDE.md]. Keep the 28 GiB MetalBackend budget. The measured 2B step is 13.10 GB device and 14.31 GB host, so there is room, but a second process counts separately.
  4. Rule 3: never held-out or validation rows in training. The smoke and runs read train shards only; the D3 gate may read validation prompts (never held-out). Amendment 3's containment check must exit 0 before step 0.
  5. The quantised rows never pool with bf16. Family lora-2b-q8, base.format and the base-file sha256 in every row; a reader keyed on optimizer_recipe alone must also key on the family id. No quantised run before the bf16 reduced row exists.
  6. Bound d' is fixed (0.02 nats steps 1-50, EMA(0.9) 0.05 after). Do not retune it after reading a result; an amendment made after a result is read is void.
  7. The merge scripts never push and never touch main's dirty peer files (.gitignore, bench/*) [V owner-merge.sh header].
