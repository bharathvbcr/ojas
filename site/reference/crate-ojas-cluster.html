Reference / Crates

ojas-cluster #

ojas-cluster implements scaling-law e-means clustering (canonical_v1, arXiv:2611.09501) and a reference full-pass Lloyd's $k$-means baseline (lloyd_fit) for ojas. It executes over multi-core CPU SIMD/BLAS (ojas-simd) and Apple Silicon Metal 4 (64x64 cooperative TensorOps and 32x32 simdgroup_float8x8 kernels via tessl) behind a single safe-Rust engine and streaming session API (#![forbid(unsafe_code)]).

Note

Following docs/modular-extensions.md, all generic clustering policy—canonical_v1 scaling laws, cosine step decay, SplitMix64 sampling and epoch permutations, Budget accounting, and streaming session state machines—lives once in ojas-cluster. When built on macOS with the default metal feature, ClusterDevice::Metal delegates GPU execution to a dedicated worker thread owning a private Metal 4 GpuRuntime and EmeansGpuRunner in tessl.

Architecture & Dispatch #

canonical_v1 Recipe & Algorithmic Mechanics #

resolve_recipe translates (global_n, d, EmeansConfig) into a ResolvedRecipe before any device memory is reserved:

  1. Subsampling (max_points_per_centroid): When set to $m \ge 1$, sample_subset_sorted deterministically draws $n_{\text{eff}} = \min(n, m \cdot k)$ sorted row indices via partial Fisher-Yates over SplitMix64. Unsampled rows receive UNASSIGNED_LABEL (u32::MAX) when capture_assignments is enabled.
  2. Batch-Size Law (BatchLaw): BatchLaw::Auto selects Quality ($C_B = 0.00439175$, capped at $\max(1, \lfloor n_{\text{eff}} / 2 \rfloor)$) when $d \le 16$, and Throughput ($C_B = 0.035134$, capped at $\text{round\_pow2}(n_{\text{eff}} / 2)$) when $d > 16$:

$$B_0 = \text{round\_pow2}\!\left(C_B \cdot k^{0.134749} \cdot n_{\text{eff}}^{0.876473} \cdot T^{0.813344}\right)$$

  1. Initial EMA Rate & Cosine Schedule: Unless overridden via EmeansConfig::alpha0, the initial EMA rate $\alpha_0$ follows the empirical scaling law clamped to $[10^{-4}, 1.0]$ and decays over total_steps via scheduled_alpha:

$$\alpha_0 = \text{clamp}_{[10^{-4},\, 1.0]}\!\left(0.8244 \cdot k^{-0.4617} \cdot B^{0.9003} \cdot n_{\text{eff}}^{-0.4498} \cdot T^{-0.1057}\right)$$

$$\alpha(s) = \alpha_0 \cdot \left(0.1 + 0.9 \cdot \frac{1 + \cos(\pi \cdot \min(s, S) / \max(S, 1))}{2}\right)$$

  1. Fractional Epoch Schedule & Closing Pass: For $T = \lfloor T \rfloor + f$ with $\lfloor T \rfloor \ge 1$, epoch_rows places any fractional remainder pass $\text{round\_ties\_even}(f \cdot n_{\text{eff}})$ before a full $n_{\text{eff}}$-row final epoch (for example, $T = 2.6$ on $n = 100{,}000$ executes [100_000, 60_000, 100_000]). During the final epoch, every batch accumulates closing sufficient statistics alongside EMA updates (f64 pass_sums + f64 divide on CPU; f32 GPU slice/CSR pass_sums + f64 host closing divide on Metal) so EmeansFit::centroids are finalized from the full closing pass, retaining the latest EMA centroid for any cluster with zero closing-pass assignments.
  2. EMA Update & Gumbel Dead-Cluster Split Revival: Each mini-batch updates cluster usage $u_j \leftarrow (1 - \alpha) u_j + \alpha n_j$ (or $u_j \leftarrow \alpha n_j$ when $\alpha = 1$) and blends centroids with exact weight == 1.0 replacement when $u_{\text{old}} = 0$. Every 5th mini-batch step (CHECK_UNUSED_EVERY = 5; (step + 1) % 5 == 0 when unused_threshold > 0.0, i.e., 0-based step in $\{4, 9, 14, \dots\}$ or 1-based $s \equiv 0 \pmod 5$), clusters with $u_j < \tau \cdot \bar{u}$ ($\tau = 0.1$ for $d > 2$, $0.0$ for $d \le 2$) are revived by splitting live donor clusters ranked by stateless SplitMix64 Gumbel keys $g_j = \ln(u_j) - \ln(-\ln U_j)$ with alternating $\pm\epsilon$ coordinate perturbations (split_epsilon = 1e-4), plus 1-ULP deterministic tie separation when (1 +/- eps) underflows representation precision.

Important

Every host scratch buffer (Scratch<T>) and Metal pool slab (OjasBudgetLedger -> tessl::PoolLedger) charges ojas_core::Budget before allocation and refuses over-cap requests with OjasError::CapacityExceeded without mutating engine state or poisoning the GPU runtime. Dropping EmeansSession and EmeansEngine (or calling EmeansEngine::trim_pool) returns Budget::live_bytes() to 0.

Usage #

One-Shot Fit & Assignment #

rust
use ojas_cluster::{emeans_assign, ClusterDevice, CpuMath, EmeansConfig, EmeansEngine};
use ojas_core::{Budget, Tensor};

let budget = Budget::new(256 * 1024 * 1024);
let engine = EmeansEngine::new(
    ClusterDevice::Cpu {
        threads: None,
        math: CpuMath::DeterministicFma,
    },
    &budget,
)?;

let x = Tensor::from_f32(&rows, &[n, d], &budget)?;
let mut cfg = EmeansConfig::new(k);
cfg.nepochs = 2.6;
cfg.seed = 42;

let fit = engine.fit(&x, &cfg)?;
let (labels, total_obj) = engine.assign(
    &x,
    &fit.centroids,
    cfg.spherical,
    cfg.assignment_chunk_size,
)?;
let (_one_shot_labels, _one_shot_obj) =
    emeans_assign(&x, &fit.centroids, cfg.spherical, engine.device(), &budget)?;

Out-of-Core Streaming (EmeansSession) #

EmeansSession accepts arbitrary [m, d] F32 or Bf16 (Host or Mapped) row chunks bounded by 1 <= m <= session.remaining_in_batch(), returning (AccumulateStep, Option<Vec<u32>>) and producing a 0-ULP bit-identical EmeansFit relative to EmeansEngine::fit_with_init:

rust
use ojas_cluster::EmeansSession;

let mut session = EmeansSession::begin(&engine, global_n, &init_centroids, &cfg)?;
let num_epochs = session.recipe().epoch_rows.len();
while session.epoch() < num_epochs {
    while session.remaining_in_epoch() > 0 {
        while session.remaining_in_batch() > 0 {
            let take = next_chunk_len.min(session.remaining_in_batch());
            let (step, _maybe_closing_labels) = session.accumulate(&next_chunk(take))?;
            if step.batch_ready {
                let _revived = session.update()?;
            }
        }
    }
    let _stat = session.end_epoch()?;
}
let fit = session.finalize()?;

Test Suites (18 integration tests) #

  • tests/recipe_and_rng.rs (4 tests): canonical_v1 batch-law resolution against upstream Python values, fractional epoch ordering and invalid-bound refusals, SplitMix64 sampling/permutations and spherical prescaling, and collapsed-split 1-ULP separation across -0.0, subnormals, and finite extremes.
  • tests/cpu_and_lloyd.rs (8 tests): CpuMath::DeterministicFma and CpuMath::Exact multi-thread bit-identity and thread-ceiling refusal, pinned-thread vs Accelerate panel parity, f64 closing-pass accumulation without f32 stall, spherical zero-row/unassigned edge cases, e-means T = 2.6 vs 25-iter lloyd_fit convergence, and fail-closed non-finite/overflow/Budget refusals.
  • tests/metal_and_session.rs (6 tests): faiss/contrib/e_means canonical_v1 golden parity across CPU and all three Metal precision lanes, resident fit vs streaming EmeansSession bit-identity, k = 1024 multi-epoch Gumbel revival repeat-run and streaming-vs-resident 0-ULP bit-identity across all three Metal 4 precision lanes, cross-runtime Mapped (SharedBuf) zero-copy safety and Budget trim recovery without GpuRuntime poison, 200-iteration engine reuse and early-drop zero-leak checks, and dtype/state-machine refusals.
